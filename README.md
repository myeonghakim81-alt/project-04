# 탱크 아케이드 - 프로토타입 (v0.15)

`tank_arcade_gdd.md` 기획서의 "11. 프로토타입 범위 제안 (v0.1 MVP)"를 기반으로 만든 플레이 가능한 웹 프로토타입입니다.
순수 HTML5 Canvas + Vanilla JS로 제작되어 별도 빌드 과정 없이 바로 실행할 수 있습니다.

## 실행 방법

정적 파일이므로 아무 로컬 서버로 열면 됩니다. 예)

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

(`index.html`을 파일로 직접 더블클릭해서 열어도 대부분의 브라우저에서 동작합니다.)

## 조작

**데스크톱 (키보드)**

| 키 | 동작 |
|---|---|
| 방향키 / WASD | 8방향 이동 (탱크 몸체가 이동 방향으로 회전) |
| Space | 현재 선택된 무기로 발사 (연사 아님 - 누를 때마다 1발, 쿨다운 내 재입력은 무시) |
| Shift | 일반 미사일 ↔ 특수(파괴) 미사일 전환 |

**모바일 (터치)**: `(hover: none)` 또는 `(pointer: coarse)` 환경(터치 기기)에서는 키보드 안내 대신 화면 하단에 가상 조이스틱(이동)과 발사/무기전환 버튼이 자동으로 표시됩니다. 화면과 캔버스도 뷰포트 폭에 맞춰 반응형으로 축소됩니다.

## 구현된 MVP 범위

기획서 11번 항목 기준 구현 내역:

1. **필드/미로**: 배틀시티 스타일 파괴 가능한 벽 필드. 스테이지(시드)마다 절차적으로 생성.
2. **플레이어 탱크**: 이동, 일반 미사일(벽에 막힘, 무제한), 특수 미사일(벽+적 파괴, 탄약 제한, 소진 시 자동으로 일반 전환).
3. **적**: 평상시 순찰(랜덤 이동), 플레이어 접근 시 추적 + 조준 발사. 스테이지 11부터 저격형/돌격형/벽파괴형이 추가로 등장.
4. **파괴/피격 로직**: 특수 미사일(또는 벽파괴형 적탄)로 벽 파괴, 미사일 피격 시 적 즉사(1hp), 플레이어 3회 피격 시 게임오버(피격 후 짧은 무적시간 존재).
5. **아이템 2종**: 특수 미사일 탄약팩, 에너지 회복팩. 벽 파괴/적 처치 시 확률적으로 드랍.
6. **스테이지 클리어 루프**: 스폰된 모든 적 처치 시 클리어, 스테이지 1~100까지 진행. 100 클리어 시 엔딩.
7. **스코어**: 벽 파괴 +10 / 적 처치 +100 / 아이템 획득 +20 + 스테이지 클리어 시 남은 시간 보너스.

MVP 이후 확장으로, 스테이지를 클리어하면 다음 스테이지로 진행하며 적 수가 기획서의 난이도 곡선(1→2→4→8→…)을 따라 증가하고, 필드에 동시에 존재하는 적 수는 최대치로 제한되어 순차 스폰(웨이브 방식)됩니다. 중간보스·리더보드·절차적 맵 다양화 등은 기획서에 명시된 대로 이후 단계 과제로 남겨두었습니다.

## v0.2에서 추가된 내용

- **전체 누적 시간제**: 제한시간이 스테이지마다 초기화되지 않고, 하나의 "총 게임 시간" 풀로 누적됩니다. 스테이지를 클리어할 때마다 다음 스테이지 분량의 시간이 풀에 더해지며, 이 총 시간이 0이 되면 진행 중인 스테이지와 무관하게 즉시 게임오버됩니다.
- **스테이지 100 엔딩**: 최대 스테이지를 100으로 고정. 100스테이지를 클리어하면 "전체 클리어" 화면이 뜨고 처음부터 다시 시작할 수 있습니다.
- **적 종류 다양화 (스테이지 11부터)**: 기본형에 더해 저격형(사거리 김, 느림), 돌격형(고속 근접 접촉 피해, 발사 없음), 벽파괴형(발사한 탄이 벽도 파괴)이 확률적으로 섞여 등장합니다. 색상으로 구분됩니다.
- **탱크 크기 확대**: 플레이어/적 탱크의 충돌 반경과 그래픽을 더 크게 조정했습니다.
- **모바일 터치 지원**: 가상 조이스틱 + 발사/무기전환 버튼, 반응형 레이아웃 (v0.2.1).

## v0.3에서 추가/변경된 내용

- **특수탄 소진 유예제**: 기존의 "벽에 물리적으로 갇혔는지" 판정(플러드필 기반 고립 감지)을 제거하고, 더 단순한 규칙으로 교체했습니다 — 특수탄이 0이 되는 순간부터 `ZERO_AMMO_GRACE_TIME`(10초) 카운트다운이 시작되고, 그 안에 탄약팩을 주워 특수탄을 1 이상으로 회복하지 못하면 게임오버됩니다. 상단 HUD 중앙에 잔여 특수탄(0이 되면 남은 유예 시간)이 표시됩니다.
- **HUD 배치 변경**: 잔여 특수탄 수치를 하단에서 상단 HUD로 이동했습니다. 하단에는 현재 장전된 무기 종류만 남습니다.
- **(비공개) 히든 메커닉**: 특수탄이 0인 상태에서 발사 버튼을 `CHARGE_HOLD_TIME`(0.6초) 이상 눌렀다 떼면, 탄약을 소모하지 않는 특수탄 효과(벽+적 파괴) 미사일이 한 발 발사됩니다 (`Player.fireCharged()`, `js/game.js`의 release-edge 감지 로직). 의도적으로 게임 내 어디에도 안내하지 않는 이스터에그이므로, UI 문구나 튜토리얼에 이 동작을 노출하지 마세요.

## v0.4에서 추가/변경된 내용

- **유예 시간 연장**: 특수탄 소진 후 게임오버까지의 유예 시간을 10초 → 15초로 늘렸습니다.
- **연사 제거**: 발사 버튼을 누르고 있어도 더 이상 쿨다운마다 자동으로 계속 발사되지 않습니다. 버튼을 누르는 순간(press edge)에 1발만 발사되며, 다시 쏘려면 다시 눌러야 합니다. (연사가 있으면 "길게 눌렀다 떼기"라는 히든 조건의 릴리즈 타이밍을 구분하기 어려워지는 문제가 있었습니다.)
- **HUD 재배치**: 상단 HUD에 하트(좌) / 현재 무기 + 잔여 특수탄(중앙, 한 그룹으로 표시) / TIME(우)을 배치했습니다. 스테이지 번호는 하단으로 내려가 SCORE·남은 적과 함께 표시됩니다.

## v0.5에서 추가/변경된 내용

- **타이틀 화면**: 미로 배경 위에 탱크를 크게 강조한 "히어로 샷"과 게임 이름만 표시. 화면 아무 곳이나 클릭/탭하면 난이도 선택으로 넘어갑니다.
- **난이도 선택 (이지/노멀/하드)**: 3가지 난이도로 에너지, 시작 특수탄, 특수탄 유예시간, 스테이지 제한시간, 적 이동속도/발사속도/사거리, 아이템 드랍률, 미로 벽 밀도, 적 다양화 시작 스테이지, 스코어 배율(×1.0/×1.5/×2.2), 이어하기 가능 여부가 모두 다르게 적용됩니다 (`js/constants.js`의 `DIFFICULTIES` 참고).
- **미션 실패 시 처음부터 / 이어하기 분기**: 이지·노멀은 게임오버 화면에서 [처음부터](스테이지 1·점수 0부터 같은 난이도 재시작) 또는 [이어하기](실패한 스테이지에서 점수를 유지한 채 에너지·특수탄만 리필하고 재도전) 중 선택할 수 있습니다. 하드는 이어하기가 없어 한 번의 런으로 얼마나 높은 스테이지·점수까지 가는지가 관건입니다.
- **스코어 가중치**: 벽 파괴/적 처치/아이템 획득/시간 보너스 점수 모두 난이도별 배율이 곱해져 반영됩니다. 하드가 훨씬 위험한 만큼 배율도 가장 높습니다.
- **100스테이지 올클리어 → 난이도 선택으로 복귀**: 전체 클리어 화면의 버튼이 난이도 선택 화면으로 돌아가도록 바뀌었습니다.
- **히든 발사 버그 수정**: 창 포커스를 잃으면(alt-tab 등) 키업 이벤트를 못 받아 발사 입력 상태가 `true`에 고정되는 문제가 있어, `blur` 이벤트에서 입력 상태를 전부 초기화하도록 방어 코드를 추가했습니다. 실제 플레이 시퀀스(특수탄 3발 소진 → 길게 눌렀다 떼기)로 히든 강화 발사가 정상 동작함을 확인했습니다.
- **CSS 버그 수정**: `#stage-container`에 걸려있던 `line-height:0`이 하위 오버레이 텍스트에 상속되어 여러 줄 텍스트가 겹쳐 보이는 문제가 있어 제거했습니다 (canvas는 이미 `display:block`이라 애초에 불필요했던 규칙).
- **히든 발사 로직 재작성 (진짜 원인 수정)**: 이전의 `blur` 초기화만으로는 부족했습니다. 진짜 원인은 발사 입력을 `requestAnimationFrame` 루프 안에서 "이전 프레임 대비 지금 눌려있는가"로 비교하던 방식이었는데, 이 비교는 `update()`가 `game.state==='PLAYING'`일 때만 도니, 발사 버튼을 누른 채로 죽거나(게임오버) 스테이지가 전환되면 그 비교가 멈춰버려 다음 판의 첫 입력이 씹히고 이후 홀드 시간 계산도 어긋났습니다. 이제는 `keydown`/`keyup`(및 터치 버튼의 `pointerdown`/`pointerup`) 이벤트에서 직접 `performance.now()`로 누른 시각과 뗀 시각을 기록해 판정하도록 재작성해서, 프레임 루프나 게임 상태 전환과 무관하게 항상 정확합니다. 홀드 임계값도 0.6초 → 0.45초로 낮췄습니다.

## v0.6에서 추가된 내용

- **중간보스 (5의 배수 스테이지)**: 기획서 5번 항목의 중간보스를 구현했습니다. `BOSS_STAGE_INTERVAL`(5) 배수 스테이지에서는 일반 웨이브 대신 커다란 보스 탱크 1기만 등장합니다. 시각적으로 1.6배 확대되어 그려지고, 체력바가 위에 표시되며, `bossHpForStage()`로 기본 6회 피격(스테이지 100 부근에서는 최대 10회)을 견딥니다. 벽파괴형 특성을 가지고 있고, 발사 시 3-way 탄막을 씁니다. 처치 시 점수(`SCORE_BOSS`, 난이도 배율 적용)와 아이템 드랍이 확정으로 주어집니다.
- **보스 직후 스테이지의 강화 개체**: 보스를 넘긴 바로 다음 스테이지는 다시 적 1기만 등장하되, 이동 속도가 30% 빠르고(`VETERAN_SPEED_MUL`) 플레이어를 향해 접근하면서 좌우로 흔드는 회피 기동을 섞어 맞히기 어렵게 만들었습니다.
- **HUD**: 보스 스테이지에서는 "남은 적" 대신 "⚠ BOSS"가 표시됩니다. 보스 격파 시 스테이지 클리어 화면 문구도 별도로 나옵니다.

## v0.7에서 추가된 내용

- **(비공개) 히든 메커닉에 시각 피드백 추가**: 기존 히든 강화 발사(특수탄 0일 때 발사 버튼을 `CHARGE_HOLD_TIME` 이상 눌렀다 떼는 것) 자체의 판정 로직은 정상 동작했지만, 아무 시각적 표시가 없어 실제로 발동했는지 체감하기 어렵다는 피드백이 있었습니다. 이제 발사 버튼을 누르고 있는 동안(특수탄 0일 때만) 탱크가 `PLAYER_CHARGE_SCALE`(1.22배)까지 `CHARGE_HOLD_TIME`에 맞춰 서서히 커지다가, 버튼을 떼서 강화탄이 발사되는 순간 원래 크기로 빠르게(약 0.12초) 줄어듭니다 (`Player.chargeScale`/`Player.charging`, `js/entities.js`·`js/game.js`). 여전히 UI 문구나 튜토리얼에는 노출하지 않는 이스터에그입니다 — 커지는 것만으로 눈치채는 것도 재미의 일부입니다.

## v0.8에서 추가된 내용

- **히든 메커닉 시각 피드백의 실제 버그 수정**: v0.7의 커지는 연출은 발사 버튼을 "누르는 순간"에만 탄약이 0인지 확인했습니다. 그래서 마지막 한 발을 쏘는 바로 그 입력으로 탄약이 0이 되고, 버튼을 떼지 않은 채 계속 누르고 있는 경우(가장 자연스러운 플레이 패턴 중 하나)에는 탄약이 0이 된 순간을 놓쳐 커지는 연출이 아예 뜨지 않았습니다(무료 강화탄 자체는 정상적으로 나갔음). 이제 `Player`가 원시 입력 상태(`fireHeld`)만 받고 매 프레임 탄약을 다시 확인해 `charging`을 계산하므로, 탄약이 0이 되는 시점과 무관하게 항상 정확합니다.
- **효과 강화**: 커지는 배율을 1.22배 → 1.4배로 키우고, 충전 중에는 탱크 색이 초록에서 노란색(특수탄 색)으로 바뀌며 은은한 발광 효과(`shadowBlur`)가 추가되어 눈에 띄지 않을 수 없게 했습니다.

## v0.9에서 추가된 내용

- **모바일 롱프레스 제스처와의 충돌 수정**: 히든 강화 발사는 발사 버튼을 `CHARGE_HOLD_TIME`(0.45초) 이상 눌러야 하는데, 이 시간대가 iOS/Android가 "길게 누르기"로 인식해 컨텍스트 메뉴·콜아웃 등 자체 제스처를 발동시키는 구간과 겹칩니다. 이 경우 OS가 우리 포인터 이벤트보다 먼저 터치를 가로채 `pointercancel`을 발생시켜, 커지는 연출이 중간에 끊기거나 강화탄이 아예 발사되지 않는 문제가 있었습니다. 발사 버튼에 `-webkit-touch-callout:none`과 `contextmenu` 이벤트 차단을 추가해 모바일에서도 항상 끝까지 홀드가 인식되도록 수정했습니다.

## v0.10에서 추가된 내용

- **모바일 히든 발사의 진짜 원인 수정**: v0.9로도 여전히 모바일에서 히든 강화 발사가 되지 않는다는 피드백이 있어 재점검한 결과, 진짜 원인은 발사 버튼(`#fire-btn`)이 가상 조이스틱과 달리 포인터를 캡처(`setPointerCapture`)하지 않고, `pointerleave`를 발사 종료 신호로 취급하고 있었던 것이었습니다. 74px 크기의 원형 버튼을 0.45초 이상 누르고 있으면 손가락이 살짝만 벗어나도(사람 손으로는 사실상 피할 수 없음) `pointerleave`가 발생해 히든 발사가 매번 중간에 끊겼습니다. 동일한 손가락 이탈 시나리오를 이전 코드와 수정된 코드에 각각 재생해 비교한 결과, 이전 코드는 즉시 충전이 취소되고 강화탄이 발사되지 않았고 수정된 코드는 정상적으로 완주함을 확인했습니다. 조이스틱과 동일하게 `setPointerCapture`를 적용하고 `pointerleave`를 발사 종료 조건에서 제거해 수정했습니다.

## v0.11에서 추가된 내용

- **Touch Events를 이중 안전장치로 추가**: v0.10 수정 후에도 실제 모바일 환경에서 여전히 히든 발사가 안 된다는 피드백이 있었습니다. Pointer Events는 캡처·경계(pointerleave/pointerout) 판정 구현이 브라우저나 임베디드 웹뷰(인앱브라우저 등)마다 미묘하게 다를 수 있어, 특정 환경에서는 여전히 신뢰하기 어려울 가능성이 있습니다. 이보다 더 원초적이고 오래된 표준인 Touch Events(`touchstart`/`touchend`/`touchcancel`)를 발사 버튼에 추가로 걸었습니다 — `touchend`는 손가락이 화면 어디로 움직였든 항상 `touchstart`가 시작된 요소로 전달되므로 "버튼 밖으로 벗어남" 같은 경계 판정 자체가 존재하지 않습니다. `handleFirePress`/`handleFireRelease`는 이미 중복 호출에 안전하게 가드되어 있어, 기존 Pointer Events와 함께 걸어도 충돌 없이 이중 안전장치로 동작합니다.

## v0.12에서 추가된 내용

- **모바일 히든 발사 최종 확인 및 정리**: 임시로 추가했던 화면 디버그 오버레이(`fireHeld`/`charging`/`ammo`/`chargeScale`/홀드 시간을 실시간으로 표시)로 실제 기기에서 확인한 결과, 히든 강화 발사 자체는 정상 작동하고 있었습니다. 원인 진단이 끝났으므로 디버그 오버레이는 제거했습니다.
- **커지는 연출에 지연 추가 (`CHARGE_VISUAL_DELAY`, 0.15초)**: 발사 버튼을 누르자마자 바로 커지기 시작해서 몇 번만 눌러봐도 이스터에그를 금방 눈치챌 수 있다는 피드백이 있었습니다. 이제 버튼을 누른 뒤 처음 0.15초 동안은 겉보기에 아무 변화가 없다가, 그 이후부터 커지고 색이 바뀌기 시작해 `CHARGE_HOLD_TIME`(0.45초) 시점에 최대 크기에 도달합니다. 실제로 뗄 때 강화탄이 나가는지 판정하는 기준(`CHARGE_HOLD_TIME`)은 그대로이며, 오직 시각 효과가 나타나기 시작하는 타이밍만 늦췄습니다.

## v0.15에서 추가된 내용 - PWA화 + 플레이스토어(Android) 패키징 기반 마련

웹페이지 형태는 그대로 유지하면서, "설치 가능한 앱"과 "플레이스토어 출시용 Android 앱" 두 갈래로 확장할 수 있도록 기반을 추가했습니다.

- **PWA(Progressive Web App) 전환**: `manifest.json`(앱 이름/아이콘/테마색/standalone 표시)과 `sw.js`(오프라인 캐싱 서비스워커)를 추가했습니다. 이제 모바일/데스크톱 브라우저에서 "홈 화면에 추가" 또는 주소창의 설치 버튼으로 이 웹페이지를 독립 앱처럼 설치할 수 있고, 한 번 로드된 후에는 네트워크 없이도 재실행됩니다. 기존 웹페이지 접속 방식은 전혀 바뀌지 않습니다.
- **아이콘 세트 생성**: `icons/`에 512/192/180/32px 및 마스커블(원형 크롭 대응) 아이콘을 추가했습니다(게임 내 탱크 그래픽을 재사용한 네온 그린 로고).
- **Capacitor 기반 Android 프로젝트 스캐폴딩**: `npx cap add android`로 `android/` 네이티브 프로젝트를 생성해 저장소에 포함시켰습니다. 이 웹 게임을 코드 수정 없이 그대로 WebView로 감싼 구조로, Android Studio로 열어 바로 빌드할 수 있습니다. 앱 아이콘(적응형 아이콘 전 해상도)과 스플래시 화면도 `@capacitor/assets`로 자동 생성했습니다.
  - `webDir`은 저장소 루트가 아니라 `www/`로 지정했습니다 (루트를 그대로 가리키면 `node_modules`, `android/`, `.git`까지 앱에 패키징되어 버리기 때문). `npm run sync:www`가 루트의 `index.html`/`style.css`/`manifest.json`/`sw.js`/`js/`/`icons/`를 `www/`로 복사하며, `npm run cap:sync`는 이 동기화 후 안드로이드 프로젝트에 반영까지 한 번에 처리합니다. `www/`는 빌드 산출물이라 git에는 커밋하지 않습니다(`.gitignore`).
  - 패키지명(`applicationId`)은 우선 `com.myeonghakim.tankarcade`로 지정해 두었습니다. **플레이스토어에 한 번 게시하면 이후 절대 변경할 수 없는 값**이므로, 실제 출시 전에 원하는 값으로 바꿔도 됩니다 (`android/app/build.gradle`의 `applicationId`, `capacitor.config.json`의 `appId`, `android/app/src/main/res/values/strings.xml`의 `package_name`/`custom_url_scheme`를 모두 같은 값으로 맞춰야 합니다).
- **이 환경에서 하지 못한 것**: 이 세션에는 Android SDK가 설치되어 있지 않고(`dl.google.com` 접근도 차단되어 있어 이 세션에서 직접 설치도 불가), 실제 APK/AAB 빌드·서명·플레이스토어 업로드는 진행하지 못했습니다. 아래 "플레이스토어 출시까지 남은 작업"에 정리된 대로, Android Studio가 설치된 로컬 PC와 Google Play Console 계정에서 이어서 진행하면 됩니다.

## 플레이스토어 출시까지 남은 작업

이 저장소에는 Android 프로젝트 뼈대(`android/`)와 아이콘/스플래시까지 준비되어 있습니다. 다만 이 개발 환경에는 Android SDK가 없고 Google 서버(`dl.google.com`) 접근도 막혀 있어, 실제 APK/AAB를 빌드하고 서명해서 업로드하는 마지막 단계는 **Android Studio가 설치된 로컬 PC**와 **Google Play Console 개발자 계정**에서 진행해야 합니다. 순서대로:

1. **패키지명 확정** (선택): 게시 후에는 절대 못 바꾸므로, `com.myeonghakim.tankarcade`를 그대로 쓸지 먼저 정하세요. 바꾸려면 `android/app/build.gradle`의 `applicationId`, `capacitor.config.json`의 `appId`, `android/app/src/main/res/values/strings.xml`의 `package_name`/`custom_url_scheme` 3곳을 동일하게 수정합니다.
2. **로컬에 Android Studio 설치**: https://developer.android.com/studio 에서 설치 (Android SDK가 함께 설치됩니다).
3. **저장소 클론 후 프로젝트 열기**:
   ```bash
   git clone <이 저장소 주소>
   cd project-04
   npm install
   npm run cap:sync   # www/ 동기화 + android 프로젝트에 웹 자산 반영
   npx cap open android   # Android Studio 실행
   ```
4. **에뮬레이터/실기기로 테스트**: Android Studio에서 Run ▶ 버튼으로 바로 실행해 실제 안드로이드 환경에서 조작감·효과음·히든 강화 발사까지 확인하세요.
5. **서명용 릴리즈 키 생성 및 서명된 AAB 빌드**: Android Studio 메뉴 `Build > Generate Signed Bundle / APK`에서 Android App Bundle(.aab)을 선택하고, 새 키스토어를 만들어 서명합니다. **이 키스토어 파일과 비밀번호는 반드시 안전하게 백업**하세요(분실 시 같은 앱으로 업데이트를 올릴 수 없습니다). Google Play App Signing을 함께 사용하면 이후 키 분실 위험을 줄일 수 있습니다.
6. **Google Play Console 개발자 계정 등록**: https://play.google.com/console 에서 최초 1회 $25 등록비를 내고 계정을 만듭니다 (사람이 직접 결제/본인인증을 해야 하는 부분이라 대신 진행할 수 없습니다).
7. **새 앱 만들기 + 스토어 등록정보 작성**: 앱 이름(예: 탱크 아케이드), 짧은 설명/자세한 설명(한국어), 스크린샷(휴대폰 최소 2장, 실제 플레이 화면 캡처 권장), 512×512 고해상도 아이콘(`icons/playstore-icon-1024.png`를 512×512로 리사이즈하거나 그대로 업로드 가능한 사이즈 확인), 기능 그래픽(1024×500, 별도 제작 필요), 카테고리(게임 > 아케이드) 등을 입력합니다.
8. **개인정보처리방침 URL 준비**: 이 게임은 서버 통신이나 개인정보 수집이 전혀 없지만, 플레이 콘솔은 대부분의 앱에 개인정보처리방침 URL을 요구합니다. "수집하는 정보 없음"이라는 내용의 간단한 페이지를 만들어 URL만 등록하면 됩니다 (예: 이 저장소를 GitHub Pages로 올린 뒤 같은 도메인에 `privacy.html` 한 장 추가).
9. **콘텐츠 등급 설문 + 데이터 안전 섹션 작성**: Play Console 안내에 따라 설문에 답합니다. 폭력성은 만화적/추상적 수준(탱크 대전)이라고 사실대로 기재하면 됩니다. 데이터 수집 항목은 전부 "없음"으로 표시하면 됩니다.
10. **내부 테스트 트랙에 먼저 업로드**: 처음부터 프로덕션(전체 공개)에 올리지 말고, 내부 테스트 → (원하면) 비공개/공개 테스트를 거쳐 실제 기기에서 한 번 더 검증한 뒤 프로덕션으로 승격하세요.
